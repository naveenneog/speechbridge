# Unknowns

Register of what we did not know, and how each was closed. States: `OPEN` · `RESEARCHED` ·
`ASSUMED` · `RESOLVED` · `MOOT`.

| ID | Packet | Unknown | State | Resolution | Source / risk |
|----|--------|---------|-------|------------|---------------|
| U-1 | P-1 | Can we use an API key at all in this tenant? | **RESOLVED** | **No.** `disableLocalAuth=true` is force-applied by policy on every Cognitive Services account, including a brand-new one. `az ... keys list` → `BadRequest: Failed to list key`. Entra ID is the only path. | Own measurement, 2026-08-10 |
| U-2 | P-1 | Does the Speech SDK accept an Entra token, and in what format? | **RESOLVED** | Yes — `SpeechConfig.fromAuthorizationToken("aad#{resourceId}#{entraToken}", region)`. Proved by synthesizing 105,644 bytes of audio against a key-less resource. Requires a **custom subdomain** on the resource. | Own spike, 2026-08-10; docs: `speech-service/how-to-configure-azure-ad-auth` |
| U-3 | P-1 | Can we avoid putting a broad Entra token in the browser? | **RESOLVED** | Yes. `POST https://{subdomain}.cognitiveservices.azure.com/sts/v1.0/issueToken` with `Authorization: Bearer {entraToken}` returns a **929-char Speech-scoped STS token**. The regional `*.api.cognitive.microsoft.com` host rejects this with 400 — the custom subdomain is required. | Own spike, 2026-08-10 |
| U-4 | P-1 | STS token lifetime? | **RESEARCHED** | 10 minutes. We refresh at 8 minutes (80%) to leave margin. | `learn.microsoft.com/azure/ai-services/authentication` |
| U-5 | P-5 | Does `TranslationRecognizer` still stream partial results and support multiple targets? | **RESOLVED** | Yes to both. Measured: 4 `recognizing` events, first at 1548 ms, final at 2919 ms, translating one utterance into `es` + `hi` + `kn` simultaneously. | Own spike, 2026-08-10 |
| U-6 | P-5 | Why does the SDK fail with WebSocket 1006 under Node? | **RESOLVED** | Node's **native global `WebSocket`** (experimental WebSocket-over-HTTP/2) is incompatible with the Speech service. `delete globalThis.WebSocket` forces the `ws` package fallback and both STT and translation connect immediately. **Browsers are unaffected** (their `WebSocket` is standard). Only affects Node-side tests/tools. | Own spike, 2026-08-10 → ADR-0004 |
| U-7 | P-5 | Can we speak the translation directly from the recognizer, or must we chain a synthesizer? | **RESEARCHED** | The `Synthesizing` event gives direct speech-to-speech **but only with a single target language** — docs: "Do not add multiple target translation languages." Our design is one target per direction, so the built-in path is available. We nonetheless chain an explicit `SpeechSynthesizer` to control voice per language and to allow barge-in cancellation. | `speech-service/how-to-translate-speech` → ADR-0005 |
| U-8 | P-5 | What is the latency knob for the pause before a final result? | **RESEARCHED** | `Speech_SegmentationSilenceTimeoutMs`, integer **100–5000 ms**, default 500. We use 350 ms to favour responsiveness. `Speech_SegmentationStrategy="Semantic"` exists (SDK ≥1.41) as an alternative. | `speech-service/how-to-recognize-speech` |
| U-9 | P-3 | Will the TTS output be re-captured by the mic and re-translated in a loop? | **ASSUMED → guarded** | Assumed yes on open speakers; `TranslationRecognizer` has **no built-in echo cancellation** (unlike Voice Live). Mitigated by a mic-gating state machine that mutes recognition during playback, plus browser AEC via `getUserMedia({ echoCancellation: true })`. **Risk if wrong:** none (gating is harmless). **Risk if insufficient:** feedback loop → detector is `tests/micGate.test.ts` + the on-screen "muted while speaking" indicator. | `speech-service/voice-live` (contrast); ADR-0006 |
| U-10 | P-2 | Which voice should each target language use? | **RESOLVED** | Enumerated 764 voices from the live service. Multilingual neural voices exist for en/es/fr/de/zh/pt/ko/it; hi/kn/ta/te/ja/ar/ru have locale-specific neural voices only. Catalog encodes the verified `shortName` per language. | Own enumeration via `getVoicesAsync`, 2026-08-10 |
| U-11 | P-6 | Can the browser autoplay the translated audio? | **ASSUMED → guarded** | Browsers block audio until a user gesture. The demo always starts from an explicit "Start session" click, which satisfies the gesture requirement for the page. **Risk if wrong:** silent playback → detector is the explicit `audio-blocked` UI state, which tells the user to click once. | Browser autoplay policy (platform behaviour, not Azure-specific) |
| U-12 | — | Is continuous language identification usable to auto-detect who is speaking? | **RESEARCHED → deferred** | Not for our stack: continuous LID is documented as supported for **speech-to-text only** in the JavaScript SDK, not for translation. Open-range multilingual translation exists via the v2 endpoint but returns **no interim results**, which would cost us live captions. Deferred to roadmap "Later"; explicit speaker turns used instead. | `speech-service/language-identification`; `how-to-translate-speech` |
